# Verification guide

## Automated checks

The current backend is JavaScript/Fastify with PostgreSQL/PostGIS. Start `docker compose -f infra/compose.local-database.yml up -d --wait`, install with `npm --prefix backend ci --ignore-scripts`, then run `npm --prefix backend test` on Node.js 24 LTS. Tests use a dedicated database whose name ends in `_test`; the reset helper refuses other database names. `./tools/check.ps1` runs the backend, admin and Flutter checks together. The legacy Python backend test file has been replaced by the JavaScript tests in `backend/test/`.

Run backend integration tests against the dedicated PostgreSQL test database, admin helper tests with Node, and Flutter analyze/tests as documented in each component. Never run reset helpers against the interactive demo database. Critical checks cover:

1. Unauthenticated requests, fake production tokens, non-admin access, and nonparticipant conversation access are rejected.
2. Search rejects radius outside 1–39 km and invalid blood groups/coordinates; results exclude private fields and unavailable, cooling-down, blocked, banned, or cross-country donors.
3. Calendar-month cooldowns handle month ends/leap years, reject future dates, cannot be shortened by older donation logs, persist through travel, and preserve an explicit offline choice.
4. Reports can only target a conversation peer; pending reports do not ban; only reviewed money requests can impose the permanent ban; ban enforcement spans countries and message/call routes.
5. Profile fields are validated, BMI is computed server-side, and account deletion prevents reuse of the same active session.
6. Calls reject unconfigured media services and unauthorized participants; credentials are room-scoped and unavailable before consent.
7. UI handles narrow screens, landscape, large text, light/dark themes, loading, empty data, denied permissions and server errors.
8. Donation history is owner-only; completion reminders are restricted to the matched pair and survive travel. Facility/location/country validation rejects missing or blank new details; migrated legacy rows preserve nulls. Completion creates a receipt for the matched donor and seeker, without recording a donation or starting cooldown; cancellation and repeated completion do not create extra receipts.
9. A request-linked donation saved twice, including concurrent retries, produces one record and one recorded receipt. Manual retries with the same owner/key and recorded fields also create one record; reusing a key for changed details returns 409 and different owners cannot retrieve each other's result. No donation/Later do not create history or a cooldown; each person's No must leave the other person's Yes possible. Dismissal persists across restart; unknown or unrelated participant receipt IDs are denied. Export/deletion cover both history and receipt states, without exposing internal idempotency keys.

See `docs/DELIVERY.md` for checks actually run, rather than treating this list as evidence.

## Pixel acceptance walkthrough

Start the local API, reverse port 8000 over USB, and install the debug demo build. All records used here must be fictional.

1. Confirm the blood-drop handshake logo, short community signature and visible local-demo status. Check the installed Android launcher icon is centered and unclipped. Enter demo; verify home, availability, country, and five navigation destinations. At tablet width, verify side navigation.
2. Open Find donors near the sample Dhaka location: O+ results should load automatically on a full-screen map below floating filters. Confirm Nadia and Arif share an approximate-area bubble with a count of two. Drag the exposed map with one finger: only its camera should move. Tap the bubble: the bottom sheet must expand to its matching donor cards. Drag/scroll the sheet without panning the map; test Expand, Collapse and All areas buttons. Change blood group and radius (1–39 km); stale previous-group results must not reappear. Panning must not change the saved location or issue new searches. Cards contain only display name, blood type, city and distance band. No donor photo or precise donor coordinates appear. Simulate unavailable tiles and verify the donor sheet remains usable; zoom/recentre buttons must work without dragging.
3. Open a donor conversation, send a sample message, leave and return, and verify persistence. Confirm no phone number or dialer handoff exists.
4. Try calling with no media configuration and verify an honest unavailable message, not a connected timer.
5. Edit height/weight and verify BMI. Check the shared donation-status card in Home and Profile: available, voluntarily offline, and cooldown with remaining time and a local end date/time. Turn availability off, record a fictional donation with its date, hospital/blood bank, area and country, and verify history plus the enforced pause. Changing willingness during cooldown must not end it; expiry preserves the chosen preference. Reopen the app and confirm both records and status remain correct.
6. Choose automatic foreground location or a manual country/area. Confirm the entire country, area and coordinates update together; a failed geocode must not silently search the previous country. Confirm cooldown and voluntary availability persist and regional messages are not silently copied.
7. Submit a fictional money-request report; open the admin console, inspect evidence, enter a review note, and dismiss or ban the fictional target. Verify ordinary members cannot open admin data.
8. Verify blocking, account export and confirmed deletion using disposable demo data. Do not delete the primary demo identity during an ordinary walkthrough.
9. Test 200% text size, landscape, TalkBack, denied location and microphone permissions, airplane mode, retry, sign-out, app restart and navigation back.
10. Add an optional fictional profile picture. Verify nonparticipants cannot fetch it, even using its account ID. Create a request, accept from an invited donor, verify only the pair sees the photo/map, then cancel and verify access is revoked.
11. Invite two eligible donors and accept concurrently; exactly one must win. Verify the other donor receives a personalized thanks and no meeting coordinates/photo. Confirm a donor can withdraw from an accepted request.
12. Set up local ntfy as described in `docs/NOTIFICATIONS.md`. Enable notifications, leave the app, and create a request from the other fixture. Verify a generic OS notification, tap to Requests and verify the authenticated details. Repeat after terminating the app process without force-stop. Test disable/sign-out/cooldown suppression.
13. Complete an accepted request and check both participant roles. Verify role-aware confirmation wording, Later, independent No choices and a seeker-first Yes. The donor receives the history entry/cooldown while the seeker retains their own profile and sees only the matched outcome. Simultaneous Yes submissions create one row. Verify the compact Home switch/settings sheet, readable remaining time, private history, failed-save retry and large text. Confirm pending prompts do not interrupt calls or another route.
14. From each matched participant, submit a fictional concern with explanation and screenshots. Verify report creation success is distinct from attachment success, partial uploads can retry without duplicate reports/images, blocking does not disable reporting, and cancellation does not prevent a matched report. Reject invalid MIME/content, oversized files, image bombs and a fourth attachment. The accused and unrelated members must not retrieve reporter evidence. Admin country switching/sign-out/background must clear image bytes/blob URLs and stale image requests must not repopulate the previous report.
15. Open My reports from Requests and Profile; verify only the submitter's records, awaiting-review status, timeline and evidence. Review a fictional report and verify Reviewed, a public outcome and review time, with no internal moderator note. Confirm a generic review alert during cooldown/offline and after travel, and that opening the original-country report leaves the current country unchanged. Check duplicate/concurrent resolutions produce only one review event/outbox entry and failed review transactions do not deliver an alert. Delivery can retry, so clients must tolerate duplicate pushes. Test sign-out, background/private image cleanup and unavailable/deleted reports.
16. Select each height unit (cm, m, in, ft/in) and weight unit (kg, lb, st/lb). Check paired fields at 200% text, decimal commas, invalid values and unchanged boundary values while cycling units. Save 5 ft 6 in and 150 lb in a disposable fixture: the API must receive 167.64 cm and 68.0388555 kg and BMI must be 24.2. Reload preferences per account, and verify a location update while editing is preserved on save. Measurement tests and the Profile integration test automate these cases.
17. Pan during an in-flight donor search and confirm completion does not snap the camera back. Zoom/recenter should animate briefly, stop on a new pointer gesture and jump immediately with reduced motion. Verify search progress and result semantics, marker selection, sheet controls and stable map attribution on narrow/landscape layouts.
